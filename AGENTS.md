# AGENTS

- Design source: the NSWP spec (`../Nostr-Spatial-Web-Protocol--NSWP-/spec.md`), Part II and §20. BitPortal is one client of that protocol and must keep a working no-BitBlocks mode (`?plain=1`).
- Before finishing a change: `npm test`, `npm run typecheck`, `npm run vendor:check`, `npm run previews:check`, `npm run build`.
- **Saved doors and the room (spec §14.1):** saved places (`src/shared/saved.ts`) and the room's layout (`src/shared/room.ts`) stay in this browser. Never publish them or send them anywhere without the owner's decision. A saved door keeps its place on the wall for as long as it is saved; don't reorder the wall. The room draws built-in furniture only: nothing from a layout may cause a request to another site.
- **Lobby privacy (spec §5.7):** listing a world must not contact its origin. Only opening a door or the Airlock may. No remote images, fonts or scripts; the CSP enforces same-origin for all three.
- **Previews (spec §5.8):** a door shows a preview only from BitPortal's own mirror (`public/previews/`, filled by `npm run previews`), and only after the bytes match the hash in the signed announcement. Anything not mirrored waits until the door is opened. All of that is decided in `src/shared/preview.ts`; the list and the hall must not fetch a preview any other way. Never show one unasked for a world with a content warning or a world outside the visitor's chosen lists.
- Vendored code under `vendor/` and `public/fonts/` is generated by `npm run vendor` from clean sibling checkouts. Never edit it by hand. Gaps found in a block go back to that block's repo, not into a local patch.
- BitBlocks conventions apply: lowercase hex `pubkey` (D1), `--bitportal-*` CSS properties (D3), snake_case error codes (D4), one version number (D6).
- **Sign-in:** BitLogin is the only session source. Pass its signer to code explicitly (`src/shared/session.ts`); never read `window.nostr` elsewhere. Check every signature a signer returns. `<bitlogin-auth>` must stay in one fixed place in the page: moving or removing it ends its worker. Never create or sign in to a BitLogin account from automation; use `/publish/?signer=test`.
- Never commit keys. The curator key is at `~/.config/nswp/bitportal-curator.key`.
- Deploying, publishing events to relays and changing the starter set's contents are outward-facing: the repo owner approves each.
- **Look:** dark only. One colour of light, `--bitportal-accent`; the worlds supply every other colour through their doors. Three shapes: the arch is a door, the block (a notched corner, a small square) is a bit, the grid is the space. Panels and buttons are square or notched, never rounded. The Airlock stays plain: nothing there may compete with the address. The 3D ground is `src/shared/environment.ts`, used by the room and by the live room on the landing page; a 3D door is `src/shared/door3d.ts`. The landing page's room (`src/lobby/hero.ts`) must draw from the same data as the list and contact nothing the list doesn't, and the page must be whole without it.
- UI copy: plain language, sentence case, say what a button does. The domain a door leads to is always shown in full, in the monospace face.
